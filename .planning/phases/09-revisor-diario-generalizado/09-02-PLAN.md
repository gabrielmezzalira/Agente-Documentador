<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo cliente → GitHub Actions runner | cron executa em ambiente controlado do GitHub; somente leitura por contrato |
| GitHub Actions runner → POST /ingest/revisao | payload com diff potencialmente grande; validado pelo schema Pydantic no backend |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09B-01 | Information Disclosure | diff_agregado no payload — código-fonte exposto ao backend DocuData | low | accept | por design do sistema — o backend precisa do diff para revisar; operador Railway tem acesso aos logs |
| T-09B-02 | Tampering | revisor_agent.py — script copiado para o repo cliente pode ser modificado | low | accept | gerente controla o repo; o script é open e auditável; sem privilégios elevados |
| T-09B-03 | Denial of Service | cron manual via workflow_dispatch poderia ser abusado para gerar muitas chamadas Gemini | low | accept | workflow_dispatch requer acesso ao repositório (autenticação GitHub); gemini_api_key é do projeto |
| T-09B-04 | Tampering | prompt injection via mensagens de commit na lista_commits | low | accept | lista de mensagens vai para contexto do prompt como texto puro; Gemini não executa código |
| T-09B-SC | Tampering | nenhum pacote npm/pip/cargo instalado nesta fase | low | accept | revisor_agent.py usa apenas Python stdlib; revisor.yml não tem pip install steps |
</threat_model>
