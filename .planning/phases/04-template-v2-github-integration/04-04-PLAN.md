<objective>
Implementar a integração com GitHub via commit hook: um endpoint `POST /ingest/commit` que recebe metadados do commit, usa Gemini para extrair conteúdo estruturado (mudança, decisão, tecnologias, impacto no backlog), e salva uma ingestion com `tipo_documentacao='commit'`. Um script bash de git hook (`post-commit`) detecta commits com `[docudata]` no subject e envia o payload automaticamente.

Depende do Plan 04-01 para que `tipo_documentacao='commit'` seja válido na CHECK constraint do banco.
</objective>

    ```python
    @router.post("/ingest/commit", status_code=201)
    async def ingest_commit(payload: CommitPayload):
    ```

    Lógica do endpoint:
    1. Verificar que o projeto existe (query `projects` table; se não existir: 404)
    2. Montar prompt para Gemini com os dados do commit:
       ```
       Analise este commit de um projeto de dados e extraia informações estruturadas.
       
       Commit: {commit_message}
       Autor: {author}
       Data: {date}
       Mudanças (diff stat): {diff_stat or 'não informado'}
       
       Retorne JSON com exatamente estes campos:
       - resumo: string descrevendo a mudança principal
       - tarefas: lista de strings com as tarefas completadas neste commit
       - decisoes: lista de strings com decisões técnicas tomadas
       - problemas: lista de strings com problemas identificados ou resolvidos
       - contexto_cliente: string com impacto no backlog ou no cliente (vazio se não aplicável)
       - proximos_passos: lista de strings com próximos passos implicados pelo commit
       
       Retorne APENAS JSON válido, sem markdown, sem backticks.
       ```
    3. Chamar `ChatGoogleGenerativeAI(model="gemini-2.5-flash", google_api_key=os.environ["GEMINI_API_KEY"])` e parsear com `JsonOutputParser()`
    4. Se o parse falhar: usar conteúdo mínimo com `resumo=commit_message`, outros campos vazios
    5. Adicionar campo `"tecnologias": []` ao extracted_content (padrão dos outros tipos)
    6. Salvar no Supabase:
       ```python
       client = get_client()
       client.table("ingestions").insert({
           "id": str(uuid.uuid4()),
           "project_id": payload.project_id,
           "sprint_number": payload.sprint_number,
           "file_name": f"commit:{payload.commit_hash[:7]}",
           "file_type": "commit",
           "tipo_documentacao": "commit",
           "extracted_content": extracted_content,
       }).execute()
       ```
    7. Retornar `{"status": "ok", "commit": payload.commit_hash[:7]}`

    Conteúdo do script:
    ```bash
    #!/bin/bash
    # DocuData Git Hook — post-commit
    #
    # Instalação (executar uma vez no repo do projeto):
    #   cp <caminho-deste-arquivo> .git/hooks/post-commit
    #   chmod +x .git/hooks/post-commit
    #
    # Variáveis de ambiente necessárias (adicionar ao .bashrc/.zshrc ou .env do projeto):
    #   DOCUDATA_API_URL=https://seu-backend.railway.app
    #   DOCUDATA_PROJECT_ID=uuid-do-projeto-no-docudata
    #   DOCUDATA_SPRINT=1  (atualizar a cada sprint)
    #
    # Uso: incluir [docudata] no subject do commit para acionar o hook
    #   git commit -m "feat: novo endpoint [docudata]"

    set -e

    # Verificar variáveis de ambiente
    if [ -z "$DOCUDATA_API_URL" ] || [ -z "$DOCUDATA_PROJECT_ID" ] || [ -z "$DOCUDATA_SPRINT" ]; then
      echo "[docudata hook] Variáveis DOCUDATA_API_URL, DOCUDATA_PROJECT_ID e DOCUDATA_SPRINT não configuradas — hook ignorado"
      exit 0
    fi

    # Verificar se o commit tem [docudata] no subject
    COMMIT_MSG=$(git log -1 --pretty=%s)
    if ! echo "$COMMIT_MSG" | grep -q "\[docudata\]"; then
      exit 0
    fi

    # Coletar metadados do commit
    COMMIT_HASH=$(git log -1 --pretty=%H)
    COMMIT_FULL_MSG=$(git log -1 --pretty=%B | head -20)
    AUTHOR=$(git log -1 --pretty=%an)
    DATE=$(git log -1 --pretty=%aI)
    DIFF_STAT=$(git diff HEAD~1 HEAD --stat 2>/dev/null | tail -1 || echo "primeiro commit")

    # Montar JSON e enviar ao backend
    PAYLOAD=$(printf '{"project_id":"%s","sprint_number":%s,"commit_hash":"%s","commit_message":"%s","author":"%s","date":"%s","diff_stat":"%s"}' \
      "$DOCUDATA_PROJECT_ID" \
      "$DOCUDATA_SPRINT" \
      "$COMMIT_HASH" \
      "$(echo "$COMMIT_MSG" | sed 's/"/\\"/g')" \
      "$(echo "$AUTHOR" | sed 's/"/\\"/g')" \
      "$DATE" \
      "$(echo "$DIFF_STAT" | sed 's/"/\\"/g')")

    HTTP_STATUS=$(curl -s -o /dev/null -w "%{http_code}" \
      -X POST "$DOCUDATA_API_URL/ingest/commit" \
      -H "Content-Type: application/json" \
      -d "$PAYLOAD" \
      --max-time 10)

    if [ "$HTTP_STATUS" = "201" ]; then
      echo "[docudata hook] Commit registrado na Sprint $DOCUDATA_SPRINT (${COMMIT_HASH:0:7})"
    else
      echo "[docudata hook] Aviso: falha ao registrar commit (HTTP $HTTP_STATUS) — continuando"
    fi

    exit 0
    ```

    Adicionar `hooks/` ao `.gitignore` do backend se não estiver (o hook contém instruções genéricas sem segredos, então pode ser commitado, mas adicionar nota).
