**Step 0 — Migration SQL (executar manualmente no Supabase SQL Editor):**

Criar a tabela boletins_aceite com o seguinte DDL (per D-01 — tabela obrigatória):

    CREATE TABLE IF NOT EXISTS boletins_aceite (
        id                  uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
        project_id          uuid        NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
        sprint_numero       int,
        funcionalidade_ids  text[]      NOT NULL DEFAULT '{}',
        status              text        NOT NULL DEFAULT 'rascunho'
                            CHECK (status IN ('rascunho', 'enviado', 'aprovado', 'ajuste')),
        retorno_tipo        text        CHECK (retorno_tipo IS NULL OR retorno_tipo IN ('bug', 'mudanca_escopo')),
        conteudo            text        NOT NULL DEFAULT '',
        criado_em           timestamptz NOT NULL DEFAULT now(),
        enviado_em          timestamptz,
        retorno_em          timestamptz
    );
    CREATE INDEX IF NOT EXISTS idx_boletins_aceite_project
        ON boletins_aceite (project_id, criado_em DESC);

Usar text[] para funcionalidade_ids (não uuid[]) para evitar erros de serialização do supabase-py (per RESEARCH Pitfall 7).

Você é um assistente especializado em comunicação com clientes de projetos de dados do CITi. Endpoint `POST /boletins` (per D-01, D-02):
- Recebe `BoletimCreate` body
- Buscar projeto no Supabase: `client.table("projects").select("*").eq("id", body.project_id).execute()` — 404 se não existe
- Verificar `gemini_api_key` no projeto: se ausente ou vazio, levantar `HTTPException(status_code=422, detail="Este projeto não tem uma chave de API do Gemini configurada.")`
- Verificar que todos os `funcionalidade_ids` pertencem ao `project_id`: buscar `funcionalidades` WHERE `id IN (funcionalidade_ids) AND project_id = body.project_id` — se count(result) != len(funcionalidade_ids), retornar 422 com "Algumas funcionalidades não pertencem a este projeto"
- Buscar cada funcionalidade com seus `criterios_aceite` do Supabase: `client.table("funcionalidades").select("id, titulo, criterios_aceite").in_("id", body.funcionalidade_ids).execute()`
- Montar contexto textual (HumanMessage): para cada funcionalidade, incluir nome e lista de `criterios_aceite` como texto simples
- Criar `ChatGoogleGenerativeAI(model="gemini-3.5-flash-lite", max_tokens=2048, google_api_key=api_key)` — NOTA: D-02 especifica gemini-1.5-flash mas o projeto usa gemini-3.5-flash-lite no Composer (verifique disponibilidade; usar gemini-3.5-flash-lite como fallback seguro)
- Chamar `await llm.ainvoke([SystemMessage(content=_BOLETIM_SYSTEM_PROMPT), HumanMessage(content=contexto)])` em try/except → 502 se falhar
- Inserir em `boletins_aceite`: `{project_id, sprint_numero, funcionalidade_ids: [str(id) for id in body.funcionalidade_ids], status: "rascunho", conteudo: markdown, criado_em: datetime.now(timezone.utc).isoformat()}`
- Retornar `BoletimResponse` com os dados do boletim criado

Endpoint `GET /boletins/{project_id}`:
- Buscar `boletins_aceite WHERE project_id = project_id ORDER BY criado_em DESC`
- Retornar `list[BoletimResponse]`

|----------|-------------|
| client→POST /boletins | Payload contém funcionalidade_ids de origem não confiável — podem referenciar funcionalidades de outro projeto |
| project→Gemini API | Chave Gemini do projeto é sensível; nunca exposta no response |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-12-01 | Spoofing | POST /boletins — funcionalidade_ids | high | mitigate | Verificar que todos os funcionalidade_ids têm project_id igual ao do boletim antes de gerar; retornar 422 se qualquer id não pertencer ao projeto |
| T-12-02 | Tampering | POST /boletins — gemini_api_key | medium | mitigate | gemini_api_key buscada no backend via project_id; nunca incluída em nenhum response |
