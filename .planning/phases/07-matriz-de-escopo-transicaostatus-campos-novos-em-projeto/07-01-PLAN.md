## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /funcionalidades | Untrusted body: criterios_aceite array, prioridade string, sprint_alvo UUID string |
| client → Supabase | All writes go through supabase-py parameterized queries; no raw SQL from client input |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01-01 | Tampering | POST /funcionalidades — criterios_aceite array | medium | mitigate | @field_validator strips empty strings and rejects empty list with 422; supabase-py uses parameterized insert — no SQL injection |
| T-07-01-02 | Tampering | POST /funcionalidades — prioridade enum | medium | mitigate | @field_validator("prioridade") rejects any value not in {must,should,could,wont} with 422 before DB touch |
| T-07-01-03 | Tampering | SQL DDL migration — ALTER TABLE projects | high | mitigate | Migration uses IF NOT EXISTS and ADD COLUMN only — no DROP, no data mutation. Run once in controlled Supabase SQL Editor session, not via API endpoint |
| T-07-01-04 | Information Disclosure | ProjectResponse now includes contract fields | low | accept | Fields are dates and integers — no PII or secrets. No auth scope in MVP (by design decision) |
| T-07-01-05 | Tampering | sprint_alvo UUID in POST body | medium | mitigate | supabase-py will raise FK violation (400/500) if UUID doesn't reference a valid sprint — surfaced as HTTPException 500. Future: validate sprint belongs to same project |
</threat_model>
