    async def patch_funcionalidade(funcionalidade_id: str, data: FuncionalidadeUpdate):

    Implementation steps inside the handler:

    Step A — Fetch current funcionalidade row:
      Select * from funcionalidades where id = funcionalidade_id. If empty raise 404 "Funcionalidade not found". Store as `func = response.data[0]`.

    Step B — Compute agora:
      `agora = datetime.now(timezone.utc)`

    Step C — For each campo in ("status", "status_cliente"):
      Get `novo_valor = getattr(data, campo, None)`.
      If `novo_valor is None or novo_valor == func.get(campo)`: continue (no change for this field).

      Otherwise:
        Query transicoes_status: select "timestamp" where funcionalidade_id = funcionalidade_id AND campo = campo, ORDER BY timestamp DESC, LIMIT 1.
        If anterior.data is non-empty:
          ts_anterior = datetime.fromisoformat(anterior.data[0]["timestamp"]).replace(tzinfo=timezone.utc)
        Else (first transition):
          ts_anterior = datetime.fromisoformat(func["created_at"]).replace(tzinfo=timezone.utc)
        duracao = int((agora - ts_anterior).total_seconds())

        Insert into transicoes_status: {funcionalidade_id, campo, de: func[campo], para: novo_valor, autor: data.autor, timestamp: agora.isoformat(), motivo: data.motivo, duracao_fase_anterior_segundos: duracao}

    Step D — Build updates dict:
      Start with `updates = {}`.
      For each non-status field in data (titulo, descricao, criterios_aceite, prioridade, responsavel, sprint_alvo):
        If value is not None: add to updates.
      For each campo in ("status", "status_cliente") where novo_valor != func.get(campo) and novo_valor is not None:
        Add to updates.

      Special rule for status_cliente = "aprovado" (per D-03):
        If "status_cliente" in updates and updates["status_cliente"] == "aprovado" and data.data_aprovacao_cliente is None:
          updates["data_aprovacao_cliente"] = date.today().isoformat()
        Elif data.data_aprovacao_cliente is not None:
          updates["data_aprovacao_cliente"] = data.data_aprovacao_cliente.isoformat()

    Step E — If updates is empty, return func directly without calling UPDATE.

    Step F — Execute UPDATE on funcionalidades set updates where id = funcionalidade_id. Return response.data[0].

    Critical pitfall (per RESEARCH.md Pitfall 1): ALWAYS call `.replace(tzinfo=timezone.utc)` on datetime parsed from Supabase ISO strings. Never subtract naive from aware datetime — raises TypeError.

    No transaction wrapping (per D-05 decision — sem transaction explícita no MVP).
    No validation of which status transitions are allowed — gerente is sovereign (per §4.2 note in CONTEXT.md open question resolution).

    @router.patch("/{project_id}/contrato", response_model=ProjectResponse)
    async def update_contrato(project_id: str, data: ContratoUpdate):
        """Atualiza campos de contrato do projeto: datas, tolerancia e garantia."""
        client = get_client()
        check = client.table("projects").select("id").eq("id", project_id).execute()
        if not check.data:
            raise HTTPException(status_code=404, detail="Project not found")
        payload = {k: v for k, v in data.model_dump().items() if v is not None}
        if not payload:
            raise HTTPException(status_code=422, detail="Nenhum campo fornecido")
        # Serialize date objects to ISO string for supabase-py compatibility
        for k, v in list(payload.items()):
            if hasattr(v, "isoformat"):
                payload[k] = v.isoformat()
        response = client.table("projects").update(payload).eq("id", project_id).execute()
        if not response.data:
            raise HTTPException(status_code=500, detail="Failed to update contract fields")
        return _sanitize(response.data[0])

    Note: `model_dump()` not `dict()` — Pydantic v2 convention already used in this codebase.
    Note: `_sanitize` is already defined in this file — no need to redeclare it.
    Note: The date serialization loop (isoformat) addresses RESEARCH.md Assumption A2 — supabase-py may or may not accept Python date objects directly; converting to ISO string is safe.
  </action>
